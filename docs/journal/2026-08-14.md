- **The no-remote classifier is a confirmed silent-failure defect, not a theoretical fragility** — carded as `broken-remote-reports-sync-success`. Verified against real git: a configured-but-broken remote path produces the same `does not appear to be a git repository` phrase as having no remote at all, and `ErrNoRemote` completes the sync and clears the error. `git remote get-url` separates the cases by exit code (2 unconfigured, 0 configured) without touching the network. `docs/current/git-and-commit-messages.md` first described this hazard backwards — as a valid repo becoming permanently errored — and has been corrected.

- **Unverified:** the five `docs/current/` documents were written from a full read of the packages they describe, but nothing was run against them. The error-classification claims in `git-and-commit-messages.md` in particular describe string matching against git's own output text, which is version-sensitive and was not exercised against a real conflict.

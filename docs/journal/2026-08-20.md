# 2026-08-20

## commit policy design session

- combined design/planning session over the `auto-commit-regions` and `pull-only-repos` roadmap cards; both are one feature. spec drafted at `docs/future/commit-policy.md`. work order not yet started; mercurius arc pending.
- the unifying frame: a per-repo `commit_policy` (`all`/`none`/`regions` + `commit_regions` prefixes) that governs only whether sexton creates commits and for which paths. pull/push/hooks stay policy-blind except a pull preflight.
- decisions made in conversation, not obvious from the spec alone:
  - pull-only must be an explicit policy value because the cascade cannot express an empty region list — first-non-empty-wins makes `[]` indistinguishable from absent. this killed the "regions with empty list" shape early.
  - operator-made commits push under every policy. michael: if the posture needs changing, we add config later. confirmed the clean-tree path already pulls and pushes, so this is existing behavior, not new — the policy only gates the commit block in `sync()`.
  - `setError` alone judged insufficient for the squawk — michael wants an `@michael` mention. hence the `attention` severity + state and `mention_users` on the mattermost entry. mentions are attention-only in v1.
  - chat-ops acceptance (mattermost `commit <repo>`) deferred from v1, recorded in the spec's deferred section.
- mechanical facts verified against code during the session:
  - rebase requires a clean tree and autostash is forbidden by the never-discard posture, so tracked out-of-region dirt pauses the pull deliberately (preflight skip, stated in attention detail) instead of failing every poll. untracked-only dirt does not block a rebase.
  - `git.Status` already carries per-file lists — the partition point exists. gotcha for the work order: `parseStatus` keeps only the *new* path of a rename (`parts[1]` after `->`), so partitioning renames by old path needs the porcelain line's both sides; spec says a boundary-straddling rename counts as out-of-region.
  - `Pull` already has an `ErrDirtyWorkingTree` sentinel with a "shouldn't happen since we committed above" comment — that assumption becomes false under `regions`/`none`; the preflight is what keeps it from being reached.
  - scoped staging (`git add -A -- <region>`) only runs when the in-region partition is non-empty, which sidesteps the pathspec-matches-nothing error.
- second round: michael flipped the default. missing `commit_policy` now resolves to `none` (was `all`), with a warning-severity alert once per daemon start per unconfigured repo. explicit policy at any layer silences; `commit_policy: all` in a host's global `defaults` is the fleet migration. this is a breaking change on upgrade, chosen for fail-safe direction: dd ignores misspelled keys, so a typo'd policy line must land on the never-commit side rather than silently auto-committing a review queue.
- work order drafted at `docs/future/commit-policy-work-order.md`, four stages: config/resolution, git layer, sync-loop policy, surfaces. grounding discoveries beyond the spec:
  - `git.Pull` preflights with `IsDirty` (counts untracked) — stricter than the spec's untracked-doesn't-pause rule; switches to a new `IsDirtyTracked` (`--porcelain -uno`). invisible under `all` since untracked is committed pre-pull.
  - `git commit` commits the whole index: operator-staged out-of-region files mid-triage would ride into sexton's scoped commit. new index guard — commit block skipped when out-of-region entries are index-staged. third guard alongside the two conflict guards.
  - renames: partition reads pre-staging status where a move is D + ?? (git detects renames only in the index) — spec's rename sentence needs a one-line correction, flagged for triage.
  - `parseStatus` doesn't unquote porcelain C-quoted paths — partition prefix-matching needs real paths; fix also cleans quoted names in alert file lists.
- accepted residuals worth remembering: non-fast-forward push during a paused pull shows as `error` (not folded into attention; revisit if noisy), and detail-cap overflow paths changing without the visible set changing will not re-alert.
